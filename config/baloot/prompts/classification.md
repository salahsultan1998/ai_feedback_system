每条反馈独立完成以下判断，并忠实翻译全文：

一、是否可以确定有效的反馈对象、诉求或交流意图（is_valid）
1. 内容可以理解、对象或诉求明确时，is_valid=true。文字短不等于无效，例如“金币丢了”“无法充值”应保留；明确的问候感谢、游戏链接咨询也可以保留。
2. 只有乱码、无法理解的内容，返回 is_valid=false、exclusion_reason="内容无法理解"。
3. 只说“恢复成以前那样”“这样不好”等，却无法确定指的是什么或有什么实际诉求，返回 is_valid=false、exclusion_reason="缺少明确反馈对象或诉求"。不从相邻反馈猜测对象。
4. 新功能建议即使不属于已有模块，也应保留为“其他”；缺少订单、截图、原因等细节不等于对象不明确。不要因为无法核实玩家说法而排除。
5. 无效反馈仍提供如实的中文翻译或无法理解的说明，但 label、theme 必须为 ""，is_suggestion=false。有效反馈的 exclusion_reason 必须为 ""。

二、所属模块和具体主题（label、theme）
1. 每条有效反馈只选择一个最主要的模块。正文优先，客服原标签可能不准确，不能照搬。label 必须逐字匹配 labels 的一个键。
2. theme 必须逐字匹配该模块下的一个 name；主题为空或已有主题均不适用时返回 ""，不得生成新主题或强行匹配。
3. “建议”不是模块或主题。俱乐部建议归“俱乐部”；匹配优化归“玩法相关”；明确提出尚未存在的新游戏（例如多米诺）归“其他”。
4. 找回、登录、绑定及跨设备登录方式问题归“账号问题”。卡顿、延迟、掉线、游戏中断或闪退按明确描述归“游戏卡顿”；不能把中断一律译成闪退，不能自行断定是网络差。
5. 充值和付费主诉求优先归“充值”。无法充值、询问充值方法且未明确已支付，主题为“充值咨询”；付费后未到账，以及业务约定的扣款金额争议，主题为“充值未到账”。标签名称不能使译文增加“未到账”“重复扣款”等原文未说明的事实。
6. 加入、退出或切换俱乐部异常归“俱乐部”，不能因源标签写着网络卡顿而改归网络问题。战绩记录及个人相册入口、上传或恢复诉求归“个人信息页面”，有依据时选择“战绩记录”或“相册”。
7. 对局规则举报由玩家发起、系统判定。这一机制及滥用该机制的这些规则争议归“玩法相关”，不能仅因“举报”就归聊天举报、作弊或“游戏限制”。保留谁发起举报、谁将得零分、谁的得分受影响，未提及裁定结果时不补写已处罚。
8. 其他明确作弊、通牌、举报 AI 或单纯队友故意坑人的诉求按现有表归“作弊”；明确要求改善匹配时以“玩法相关”为主。聊天举报、禁言、封禁及申诉归“举报”。发牌不公平、输多赢少归“发牌&公平”。
9. 玩法准入、点赞赠送等运营限制归“游戏限制”。玩法本身的咨询和体验归“玩法相关”；活动咨询和非付费活动问题归“活动”，例如询问沙漠寻宝结束时间。金币异常丢失归“金币丢失”。
10. 含辱骂且有明确实质问题时，按实质问题归类；纯辱骂归“辱骂”，泛泛但可理解的不满归“抱怨”。问候感谢、游戏链接等明确内容按“其他”的适用主题归类。

三、是否包含产品建议（is_suggestion）
1. is_suggestion 必须是 JSON 布尔值 true 或 false，与模块分类独立。只要整条反馈包含明确的产品改进需求，就可以为 true，即使还有其他问题或个人诉求。
2. 希望新增、调整、恢复或取消某项产品功能、玩法或规则，或者提出明确对象的体验优化，返回 true。恢复已移除的个人相册、优化匹配、展示俱乐部贡献、新增游戏均属于建议。
3. 单纯故障求助、咨询、申诉、索赔或求赠金币为 false；“请帮我充值”“希望找回账号”“请解决卡顿”不能仅凭“请/希望”标成建议。投诉中另有具体功能改进请求时才标 true。
4. 若整体是在求助访问、找回或迁移自己的账号，“帮我迁移账号”“提供一种能登录该账号的方式”仍属于个人访问恢复求助，is_suggestion=false；提到缺少登录入口并不自动构成产品建议。只有明确提出独立的产品设计改进，例如希望产品新增一种登录入口或设置时，才标 true，不替玩家把个人求助扩展为新功能需求。
5. 不凭原标签“建议”判断。反馈是否值得写进最终建议摘要，会在后续另行筛选，不要为了保留或排除摘要而改变模块。

四、翻译保真
1. translation_zh 使用简体中文，忠实保留全文的主次诉求、主体、条件、否定、金额、数字、账号及玩家的怀疑程度。不得把玩家主张写成已证实事实，不添加核查结果或补偿结论。
2. 能确定的游戏名称使用表内中文。结合上下文识别口语和拼写变体；未填写或只有点号的词条没有词义，不凭模糊词猜测更具体的玩法。
3. كبوت 固定译为“打光头”，表示使对方得零分。区分打光头和被打光头、即将发生和已经发生。project 使用业务允许的英文称呼，保留 project 400 的数字，不补单位。
4. 不理解的片段如实说明，不编造含义；建议和问题不因翻译压缩而被删除。
